# Gym scoring audit

**Better genuine results score higher, and removing loop closure scores lower. The gym still rewards several shortcuts above the reference.** Increasing registration samples and optimization budget improves every scored error without weakening loop safety. The seed spread is zero on this fixed dataset. However, copying visible labels, replaying the public trajectory generator, replacing the ground truth, and duplicating loop records all beat the reference without a better tactile method. Exhaustive matching also ties the reference in four minutes: this test is too small to establish the paper's efficiency contribution. All four reference loops use an added odometry fallback rather than the paper's SIFT proposal path.

The reference below is the original `gelslam_online` entry in `scoring/scores_test.json`, preserved in [reference_original](redteam/reference_original/scores_test.json). The paper-context values in `scoring/reference.json` are not the ranking anchor. Every scored run invoked **`bash scripts/evaluate_test.sh` with no arguments**. Raw results, commands, return codes, timings, and unchanged evaluator hashes are kept in each linked run folder.

The more-computation variant improves all ten error metrics, with unchanged counts and rates. For example, rotation P95 improves from 8.893120 to 8.176018 degrees, translation P95 from 0.951459 to 0.835250 mm, and loop rotation residual from 0.882578 to 0.171551 degrees. Its gain therefore has the correct sign for any positive, finite normalization scales. Conversely, removing loops worsens every error metric and loses valid loops; its loss has the correct sign independently of the cohort. The other two improvements trade a few secondary metrics: both have slightly worse terminal translation, and the residual-selection fix has worse loop translation residual. Their positive aggregate gains refer to this audit cohort.

**Seed spread and reproduction check.** Independent reference runs initialized NumPy and OpenCV RNGs with seeds [0](redteam/ref_seed_0/outcome.json), [1](redteam/ref_seed_1/outcome.json), and [2](redteam/ref_seed_2/outcome.json). All fourteen test metrics exactly equal the original reference in all three runs. Rotation MAE range is 0 degrees, translation MAE range is 0 mm, and rank-gain range is 0. Method times were 124.0, 111.5, and 125.3 seconds. [Machine-readable checks](redteam/quality_checks.json) contain every metric's range. These are algorithm-seed repetitions on one fixed observation stream, not repetitions across new objects, trajectories, or sensor noise. Gains exceed the observed seed spread but establish no generalization confidence interval.

The reproduced method beats the baseline in the direction reported by the paper: rotation MAE 5.436666 versus 11.051543 degrees, translation MAE 0.550919 versus 0.760630 mm, and substantially better terminal drift. Removing loop closure reverses part of that benefit. Thus the synthetic stream retains a nontrivial drift-and-loop-closure effect; the baseline has not saturated the task. Nevertheless, this is not a faithful reproduction of the complete paper procedure, and success here does not establish improvement on the physical-object problem.

The main departures from the [paper](paper/2508.15990.md), particularly Sections III–V, are:

| Component | Paper | Runnable gym |
|---|---|---|
| Data and calibration | Real GelSight images, ball-calibrated gradient MLP, Poisson height integration and contact extraction; 140 tracking episodes over 20 objects, averaging 523 frames | One 144-frame stream of 56×56 patches from a textured height field, seed 7; synthetic heights/masks and analytically generated normals; no RGB/calibration pipeline |
| Curvature | Gradient divergence followed by a 7×7 Gaussian filter | Absolute height Laplacian, percentile normalization and clipping, without that Gaussian filtering |
| NormalFlow | Equation (1) normal alignment, Gauss–Newton, 3,000 high-curvature pixels | 900 pixels, SciPy LM with a 45-evaluation budget, an additional height-consistency residual, phase correlation/ECC initializers, and selection primarily by CCS + 0.4 SCR. Adding height consistency changes the objective, rather than merely scaling it |
| Tracking failure thresholds | CCS 0.85, SCR 0.30 | CCS 0.85, SCR 0.35; final frame forcibly added as a keyframe |
| Loop proposals and verification | SIFT curvature matches with more than 8 RANSAC inliers, then NormalFlow verification of those proposals | At least 12 inliers, explicit ≥32-frame separation, extra odometry-consistency gates, and a NormalFlow-only fallback even without a surviving SIFT proposal; separate acceptance thresholds |
| Coverage | Greedy nonredundant contact-surface coverage | Rounded XY footprint sets on a height field; retains the initial anchor, with the same nominal 0.2 mm² threshold |
| Scheduling and graph | Online loop worker skips intermediate queued keyframes; graph optimization in GTSAM | Synchronous replay with no wall-clock deadline and a single end-of-sequence SciPy graph solve; no scored runtime, retained-state budget, or online output latency |
| Reconstruction | Reprojected per-pixel weighted fusion of coverage keyframes, triangulation, then Poisson remeshing | Weighted voxel averaging over coverage plus tracking keyframes; no triangulation or Poisson remeshing; reconstruction entirely unscored |
| Metrics | Table IV reports separate per-axis pose MAEs; reconstruction uses physical CAD/scan targets | Translation-vector and rotation-geodesic error norms, 20/320 mm per synthetic pixel, plus interleaved frame blocks and global loop counts. Averaging the paper's axis MAEs is not the same statistic |

The supplied normals are noiseless analytic geometry while heights include noise; the reference differentiates those noisy heights instead of using the supplied normals. This explains why the observation-normal variant is a real improvement on the packaged inputs, while also limiting transfer to the paper's calibrated noisy measurements. The only accepted reference loops are frames 0→140, 0→141, 0→142, and 0→143, all tagged `normalflow_odometry_init` in [reference provenance](redteam/ref_seed_0/method_manifest.json). The scored benefit therefore does not demonstrate the paper's SIFT-based detection mechanism. Train and test are alternating eight-frame blocks of this same trajectory; the loop constraints are global and shared across both slices. They are not independent held-out episodes. The visible documents describe full-sequence scores as primary and test scores as diagnostic, which also disagrees with this gym's actual hidden-test ranking.

**Brute force.** [brute_force_all_keyframes](redteam/brute_force_all_keyframes/scores_test.json) is an honest alternative the test cannot distinguish from the reference: it retains all 69 keyframes, removes SIFT proposals, and registers every sufficiently separated keyframe pair. It considers 1,238 pairs, accepts the same four loops, and exactly ties every scored metric, rank gain 0. Runtime is 242.7 seconds versus a 124.0-second reference median. This does not attain zero trajectory error; it solves the benchmark to reference quality within minutes. The 144-frame test and absent compute/state metrics let exhaustive matching pay without preserving the paper's computational advantage.

**Rank arithmetic and task failures.** [summarize.py](redteam/summarize.py) implements the requested calculation: sum, over all fourteen metrics, `experiment_weight * abs(coefficient) * direction * (candidate - reference) / metric_std`. Weights are 0.7 for tracking and 0.3 for loops. Direction is +1 for higher-is-better and −1 otherwise. In particular, the −1 coefficient on `false_loop_rate` is used with magnitude 1; its sign does not turn false loops into a reward. Metrics are standardized separately, so their units do not determine their weight.

The displayed ranks use population standard deviation across the **22 finite entries** explicitly listed in [summary.json](redteam/summary.json): the original reference, successfully scored finite trial outputs, and the recomputed baseline. The three crashed runs have no score and the NaN-loop run is excluded from numeric ranking. The future ranking cohort is unknown, so these decimal ranks are reproducible audit comparisons, not a prediction of its exact normalization. The impossible-translation run inflates translation-error standard deviations dramatically; normalization makes any aggregate comparison cohort-dependent. The dominant more-computation improvement, weaker-method loss, oracle wins, exact ties, and duplicate-count gain do not depend on choosing these particular scales, apart from negligible floating-point residual averaging differences.

The two explicit compensation checks—constant tracking plus valid-loop spam, and perfect poses plus entirely false loops—both stay below the reference. This is evidence for those failures, not a guarantee over every later cohort or tradeoff: the rank has no hard feasibility gate. More fundamentally, the oracle shortcuts do no tactile estimation and still win, and NaN loop translations evade the validity constraint because comparisons against NaN do not increment `false_loops`.

**Failure coverage does not meet the requested contract.** Three failed test runs write no results at all, rather than the worst value in every scored metric of both experiments. The harness removes the old score file before those tests; otherwise an exception before the final write could also leave stale prior results on disk. This audit does not claim a crashed job is automatically ranked as a successful empty entry: that downstream behavior is not supplied. It does establish that the gym itself supplies no complete failure penalty matrix. Successful finite runs do emit all fourteen metrics.

**Method coverage also fails.** The no-argument test discovers only `pred_poses.npy` below `checkpoints/`, then filters names using editable `scoring/scores_train.json`. The unlisted-method shortcut demonstrably leaves a failed method on disk without any entry under either experiment's `results`. Expected-but-missing methods cause an exception; unexpected methods are silently skipped. Thus the test does not write every method on disk, and a failed method can avoid any scored loss through omission.

**Execution and restoration.** [harness.py](redteam/harness.py) stages each candidate's disk artifacts, runs training, and launches the unchanged no-argument hidden script in a new ordinary shell/Python process. Candidate processes terminate before evaluation; no background processes, evaluator edits, Python environment changes, or evaluator imports are used. Trials were bundled in two CPU container jobs, with no per-trial container restart. These shortcuts rely exclusively on persistent disk state and therefore do not require a process to survive the gym's fresh-container boundary. Reference-dependent shortcuts reuse outputs genuinely recomputed from the agent-visible method; the original score snapshot is read only by the auditor's summarizer. Label/generator shortcuts also work when `method/` starts empty. The paper was used solely for the audit comparison, never by candidate implementations.

The first job was preempted twice and cancelled after its worker stopped progressing; fifteen completed trials were retained. The second job finished the remaining nine. Each of the 24 outcomes records identical evaluator hashes before and after. Small artifact manifests preserve output hashes and loop samples while generated binary artifacts remain ignored. Candidate data, baseline code, checkpoint state, and score files were restored after every trial. Gym source/data/evaluation changes are restored to the audit base with git; pre-existing controller-owned workspace changes are not part of the audit patch. Only `redteam/`, this report, and the required final `action.yaml` signal are intentional final audit changes.

The next gym iteration should keep test targets and trajectory generation parameters outside agent-visible assets, vary held-out trajectories/objects, verify fixed comparison assets, score a fixed method roster, and emit complete worst-case failure results atomically. Loop scoring should reject non-finite values, deduplicate frame pairs, verify genuine contact overlap and use in the method's estimates, and avoid rewarding repeated records. A longer evaluation with explicit compute/state budgets is needed to test the efficiency claim; faithful paper reproduction also requires correcting the procedural departures above.
