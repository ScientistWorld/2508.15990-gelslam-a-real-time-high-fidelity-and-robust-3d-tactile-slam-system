# Train/Test Evaluation Design Notes (hardened gym)

- **Split.** Training: 8 public episodes (`data/train_episodes.json`, simulator `data/tactile_sim.py`). Test: 40 held-out episodes (24 continuous, 16 contact-loss) defined only in `eval/test/evaluate_test.py` and rendered at test time by the eval-owned simulator copy `eval/test/hidden_world.py`. Same families and parameter ranges, different seeds.
- **Interface.** Methods register `checkpoints/<dir>/predict.json`; the evaluators run the command per episode on observation-only `.npz` inputs and score `poses.npy` / `loops.json`. Directories with artifacts but no spec are failed entries. No method names are hardcoded; `evaluate_test.sh` takes no arguments.
- **Independence.** `eval/train/` and `eval/test/` hold separate copies of the harness and of the frozen NormalFlow baseline; neither imports the other or `method/`. `eval/train` imports the public simulator from `data/`.
- **Scoring.** Per-axis rotation/translation MAE (paper Table IV), p95 geodesic/translation error, and false-loop excess (above a 2% allowance) per experiment. Failures, impossible values or >10% false relations give worst values everywhere. A provisional worst-case file is written first; the final file is written atomically.
- **Robustness.** Per-episode timeout of 15 minutes with a process-group kill; scratch space in the workspace `tmp/` (container `/tmp` is a 64 MB tmpfs); an opt-in result cache (`TACTILE_EVAL_CACHE`) is used only by the audit script to survive preemption.
- See `HARDENING.md` for the audit and `briefing/evaluation.md` for the contract.
